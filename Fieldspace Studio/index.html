Fieldspace Studio — guide

What it renders

Render geodesics in ℝ³ with g(x) = I + α V(x)V(x)ᵀ, where V=(X,Y,Z) at the current time t. A Hamiltonian geodesic integrator traces camera rays and intersects signed-distance objects. This is a mathematically defined family of metrics, not the unique metric associated with an arbitrary vector field and not a true null vector field in Euclidean signature.

Wolfram-like syntax (offline subset)

Use Sin[x], Cos[y], Exp[-(x^2+y^2)], Sqrt[x^2+1], Pi, E, implicit multiplication 2 x, and user definitions a=1.5; f[x_,y_,z_]:=Sin[a x] Cos[y]. A definition X[x_,y_,z_]:=... can replace its component box. Common functions include Tan, ArcTan, Log, Abs, Min, Max, Mod, Sign, If, Piecewise, and comparisons. {...} lists work inside Piecewise.

Not a Wolfram Language kernel: symbolic evaluation, pattern-rewriting, integrals, differential equations, scoping constructs, recursive programs, compiled functions, arbitrary Mathematica package definitions, and every possible Wolfram function are not supported. A Wolfram Cloud/Engine integration needs an external service and may require credentials; it cannot be fully offline.

Metric movement and time

Enable Metric-aware movement to turn input directions into locally metric-unit vectors using g⁻¹/². The distance readout accumulates both coordinate distance and proper path length; it is not an endpoint-to-endpoint geodesic-distance solver. Spatial geometry is recomputed at fixed t. The fourth equation T[x,y,z,t] optionally advances time by dt/ds = rate T when enabled, starting frozen at t=0, T=0. Enable spacetime mode for Lorentzian proper time; outside that mode this is a time-dependent spatial metric.

Camera controls

Free-fly is the default: hold W/A/S/D for forward/back/strafe, Space for up, Shift for down, Ctrl to speed up, and R to reset. Drag to look; use Capture mouse for uninterrupted first-person movement (Esc releases). Switch to Orbit mode for object inspection; Shift+drag/right-drag pans there. Mouse wheel zooms in Orbit mode or moves forward/back in Free-fly. Movement updates continuously while keys are held. Reduce render resolution or steps if your GPU is slow.

Geodesic lattice

Choose Geodesic lattice under Reference geometry to hide objects, spheres, grid rods and floor. Three families of colored polylines use the same metric exponential-map vertices as the rods, spheres and voxel terrain. The mapping is evaluated by numerical shooting from the origin. All three modes now share the same vertex chart and polyline edges. In general the edges are not individually exact geodesics; arbitrary curvature prevents a globally exact mutually intersecting geodesic coordinate lattice. In the positive-definite Riemannian metric there are no nonzero null geodesics; spacetime mode enables null-ray integration for the shaded WebGL scenes (not for the spatial lattice overlay).

4D spacetime and proper-time clocks

Enable Simulate 3+1D spacetime metric to interpret the four fields as a spacetime geometry: h = I + α V Vᵀ, lapse N = Exp[κ T], shift β = σ V, and ds² = −N²dt² + hᵢⱼ(dxⁱ+βⁱdt)(dxʲ+βʲdt). Signature is (−+++), c=1. The GPU uses a finite-difference Hamiltonian integration of null geodesics through x,y,z,t for shaded scenes. In the geodesic-lattice overlay, the curves remain spatial geodesics on fixed-t slices, not null curves. The metric is arbitrary and does not automatically satisfy Einstein's field equations.

Press Evolve time to advance coordinate t. Clocks at coordinates x(t), with coordinate velocity v=dx/dt, advance by dτ/dt = √max(0,N² − hᵢⱼ(vⁱ+βⁱ)(vʲ+βʲ)). A clock with a negative expression under the square root is marked NON-TIMELIKE; no imaginary or fake proper time is accumulated. The clocks are prescribed coordinate worldlines, not automatically free-falling geodesics. Relative readings on a common coordinate-time slice are not a direct observation of remote simultaneous events without an additional synchronization/light-signal model.

Perlin voxel world on a spatial lattice

Choose Voxel world · Perlin lattice terrain for a seeded fractal Perlin height-map, Minecraft-like grass, dirt, stone and water blocks, and optional visible lattice edges. Terrain is generated in unbounded, deterministic 6×6 chunks centered on the camera; inactive chunks are discarded. Each cube corner and every grid/lattice point uses the same spatial exponential-map vertex chart at fixed t, with neighboring blocks sharing identical vertices. The blocks are connected by straight polygon edges between the mapped vertices. This produces a metric-deformed lattice but is not an exact global geodesic coordinate chart, and a solid 3D cube cannot have all its edges be spacetime null geodesics. Enable Follow time to recompute the lattice at successive time slices; terrain is a prescribed world, not a dynamically evolving Einstein-equation solution. The WebGL 2 terrain mesh is rasterized (not 4D null-raytraced), so its visual lighting does not bend along null geodesics. In browsers without WebGL 2, a slower Canvas 2D view is available.

Numerical caveats

GPU float precision, finite-difference derivatives and finite integration steps make this an exploratory visualizer, not a validated general-purpose geometry solver. Avoid singular or discontinuous expressions. A field equal to zero everywhere produces the ordinary Euclidean metric.
